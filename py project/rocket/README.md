# Rocket OpenRocket Optimization Experiment

This directory has been reorganized to match the current experiment structure.

Legacy scripts, plots, CSV files, and previous result workbooks have been moved
to `archive_legacy/`. The original data sources remain in this directory:

- `rocketdata.xlsx`
- `rocketdata2.xlsx`
- `rocketdata备份.xlsx`

The rocket case is a black-box simulation case. The real response is produced
by OpenRocket, not by an analytical Python function. The refactored workflow
therefore separates surrogate optimization from true simulation evaluation.
All current workflow scripts regenerate their stage outputs for the new
experiment and overwrite the corresponding workbooks. They do not resume from,
merge with, or adapt old result formats.

- `config.py`: paths, rocket bounds, target value, scheduler scope, method registry.
- `core.py`: shared data loading, TGP prediction, utility metrics, training-set saving.
- `generate_data.py`: builds `generated_data/shared_data.xlsx` and saves the
  four initial configurations under `generated_data/initial_sets/`; every run
  rewrites these generated data files.
- `run_experiments.py`: runs existing sampling methods, evaluates newly selected
  active-learning points with OpenRocket, and saves final training sets; every
  run rebuilds the selected training-set index from the current run.
- `run_ga_optimization.py`: reads saved training sets, fits TGP, and writes 20
  GA optima per final training set for OpenRocket simulation; every run rewrites
  the GA candidate table.
- `openrocket_eval.py`: shared OpenRocket `.ork` writing and simulation helper.
- `run_openrocket_simulation.py`: evaluates the GA optima with OpenRocket and
  writes simulated responses; every run re-simulates all rows in the GA
  candidate table and overwrites the simulation result table.
- `fill_openrocket_results.py`: merges OpenRocket simulation outputs back into the
  GA table and computes true `QL_value = (最大飞行高度 - TARGET_VALUE)^2`.
  It accepts only the new key structure
  `(case, method, n_initial, repeat, ga_repeat)`.
- `summarize_results.py`: rebuilds `refactored_results/summary_statistics.xlsx`.
- `methods/`: current methods only: PM, LHS, G-opt, D-opt, and K-means.
- `archive_legacy/`: old scripts, figures, and result files.

## Workflow

1. Generate shared data and save the four initial configurations:

```bash
python generate_data.py
```

Outputs:

```text
generated_data/shared_data.xlsx
generated_data/initial_sets/
generated_data/initial_sets_index.xlsx
```

The current experiment uses four initial sample sizes, `50`, `60`, `70`, and
`80`. Each initial configuration is generated once from the historical
OpenRocket response table. The candidate and test sheets contain design points
only; candidate responses are generated by OpenRocket when a point is selected.
Running this script again overwrites `shared_data.xlsx`, the four initial-set
workbooks, and `initial_sets_index.xlsx`.

2. Run active learning and save final training sets:

```bash
python run_experiments.py
```

Outputs:

```text
refactored_results/selected_datasets/
refactored_results/selected_datasets_index.xlsx
```

For each initial size and each method, active learning runs once and adds 20
new points. Each newly selected point is written into `backup.ork` and evaluated
with `OpenRocket-24.12.jar` before it is added to the training set. The final
training sets therefore have total sizes `70`, `80`, `90`, and `100`.
Running this script again regenerates the shared data, reruns all active-learning
tasks, overwrites the final training-set workbooks, and rewrites
`selected_datasets_index.xlsx` from the current run.

3. Run surrogate GA on each saved training set:

```bash
python run_ga_optimization.py
```

Outputs:

```text
refactored_results/ga_optimization_candidates.xlsx
refactored_results/openrocket_simulation_template.xlsx
```

For every final training set, GA is repeated 20 times. The candidate table
therefore contains one row per `(method, n_initial, repeat, ga_repeat)`.
It includes `ga_x1` to `ga_x5`, predicted response `ga_pred_mean`, predicted
variance `ga_pred_variance`, predicted quality loss `ga_pred_quality_loss`,
and the GA seed columns. These are surrogate-model quantities only; the true
height and true quality loss are filled after OpenRocket simulation.
Running this script again refits and reruns every GA task and overwrites
`ga_optimization_candidates.xlsx`.

4. Simulate the GA optima with OpenRocket.

```bash
python run_openrocket_simulation.py
```

This reads `ga_optimization_candidates.xlsx`, maps the five design variables
to the OpenRocket template `backup.ork`, runs `OpenRocket-24.12.jar`, and writes:

```text
refactored_results/openrocket_simulation_results.xlsx
```

The script records `最大飞行高度`, `flight_time`, `time_to_apogee`,
`max_velocity`, `max_acceleration`, and `simulation_note`.
Running this script again evaluates every GA candidate row and overwrites
`openrocket_simulation_results.xlsx`.

5. Merge OpenRocket true responses and compute final QL:

```bash
python fill_openrocket_results.py
```

Outputs:

```text
refactored_results/ga_optimization_results.xlsx
refactored_results/summary_statistics.xlsx
```

The final result table reports all 20 GA optima for each method/initial-size
combination, with the OpenRocket-simulated `最大飞行高度` and `QL_value`.
This keeps the black-box simulation result separate from the TGP surrogate
prediction.

The current OpenRocket variable mapping is:

- `ga_x1`: nose-cone length, centimeters to meters.
- `ga_x2`: body/nose outer diameter, centimeters to body radius in meters.
- `ga_x3`: nose-cone wall thickness, centimeters to meters.
- `ga_x4`: body-tube length, centimeters to meters.
- `ga_x5`: body-tube inner diameter, centimeters to body wall thickness in meters.
  The motor inner tube keeps the template radius unless it would exceed the
  available body-tube inner radius.

The default OpenRocket simulation is index `3`, matching `Simulation 4` in the
template and its default C6 motor configuration.

The EI/UCB/IMSE baselines, runtime analysis, and full 4.4 supplementary
experiment outputs remain separate follow-up work.
